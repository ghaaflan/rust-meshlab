# WASM Implementation Summary

This document summarizes the WASM support implementation for rust-meshlab.

## Implementation Approach

We chose **Emscripten compilation** instead of pure Rust reimplementation because:

1. ✅ **Exact same algorithms** - No need to reimplement complex VCGlib algorithms
2. ✅ **Full feature parity** - All native filters automatically work in WASM
3. ✅ **Single codebase** - C++ changes automatically propagate to WASM
4. ✅ **Proven approach** - Used successfully by many C++ libraries (e.g., OpenCV.js, SQLite)
5. ✅ **Maintainability** - No separate WASM-specific algorithm implementations to maintain

## What Was Implemented

### 1. Emscripten Build System

**File: `c_wrapper/build-wasm.sh`**
- Shell script to compile C++ wrapper and VCGlib to WASM using Emscripten
- Uses `emcmake` and `emmake` to configure CMake for WebAssembly target
- Produces `libmeshlab_api.a` (static library) for linking with Rust

**Key Emscripten flags:**
- `-s WASM=1` - Generate WebAssembly output
- `-s ALLOW_MEMORY_GROWTH=1` - Allow dynamic memory allocation
- `-s EXPORT_ALL=1` - Export all C functions for FFI
- `-s LINKABLE=1` - Make library linkable with Rust

### 2. Build System Integration

**File: `build.rs`** (Modified)
- Added conditional compilation based on target architecture
- **Native builds** (`target_arch != "wasm32"`):
  - Link to `c_wrapper/build/libmeshlab_api.dylib` (dynamic library)
- **WASM builds** (`target_arch == "wasm32"`):
  - Link to `c_wrapper/build-wasm/libmeshlab_api.a` (static library)
  - Include Emscripten runtime libraries

### 3. WASM JavaScript Bindings

**File: `src/wasm_bindings.rs`** (New)
- `#[wasm_bindgen]` exports for JavaScript interop
- `WasmMeshSet` class wrapper around native `MeshSet`
- JavaScript-friendly API:
  - Constructor: `new WasmMeshSet()`
  - Camel-case method names: `vertexCount()`, `applyIsotropicRemeshing()`, etc.
  - Promise-based async operations
  - Error handling with `JsValue`

**Exported functions:**
- `new()` - Create mesh set
- `meshCount()` - Get number of meshes
- `vertexCount()` - Get vertex count
- `faceCount()` - Get face count
- `applyIsotropicRemeshing(...)` - Apply remeshing filter
- `applyVertexDisplacement(...)` - Apply displacement filter
- `version()` - Get library version

### 4. Library Structure

**File: `src/lib.rs`** (Modified)
- Updated to load `wasm_bindings` module when compiling for WASM
- Conditional exports: WASM builds export both Rust API and JavaScript bindings
- Maintained single FFI layer - same C++ code serves both native and WASM

**Architecture:**
```
┌─────────────────────────────────────────────┐
│           User Code                         │
├─────────────────────────────────────────────┤
│  Native: Rust       │  WASM: JavaScript     │
│  MeshSet            │  WasmMeshSet          │
├─────────────────────┼───────────────────────┤
│        Rust FFI Layer (ffi.rs)              │
├─────────────────────────────────────────────┤
│  Native: .dylib     │  WASM: .a (static)    │
│  C++ Wrapper (meshlab_api.cpp)              │
├─────────────────────────────────────────────┤
│  VCGlib (C++ mesh processing)               │
└─────────────────────────────────────────────┘
```

## File I/O Limitations

Currently, file operations have limitations in WASM:

❌ `loadFromObjString()` - Not implemented (needs Emscripten FS)
❌ `toObjString()` - Not implemented (needs Emscripten FS)

**Solution:** Emscripten provides a virtual filesystem API:

```javascript
// Write to virtual FS
FS.writeFile('/input.obj', objFileContent);

// Call Rust/C++ function
ms.loadMesh('/input.obj');

// Read from virtual FS
const output = FS.readFile('/output.obj', { encoding: 'utf8' });
```

This requires:
1. Exposing Emscripten FS to JavaScript
2. Adding helper functions in wasm_bindings.rs
3. Updating example to demonstrate usage

## Technical Notes

### Why Static Linking for WASM?

WASM doesn't support dynamic libraries like native platforms do. Emscripten compiles everything into a single static library that gets linked with the Rust code during the final WASM compilation.

### Memory Management

WASM uses linear memory that can grow dynamically. The `-s ALLOW_MEMORY_GROWTH=1` flag allows the C++ code to allocate memory as needed, up to the browser's limit (typically 2-4GB).

### Function Exports

All C functions in `meshlab_api.cpp` are automatically exported with `extern "C"` and the `-s EXPORT_ALL=1` flag ensures they're available to Rust's FFI.

### Threading

Current implementation is single-threaded. For multi-threaded support:
- Use Emscripten's pthread emulation
- Requires SharedArrayBuffer (needs specific HTTP headers)
- Some browsers disable SharedArrayBuffer for security
